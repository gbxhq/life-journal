# Life Journal 使用规则

本目录是一套以 Markdown 为唯一数据源的生活记录库。本文件是当前记录库的数据格式和本地规则来源。执行写入前应完整阅读本文件，并同时读取 `life.config.yml`。

> 本 Demo 中所有人物、地点和事件均为虚构演示数据。

## 目录结构

```text
diary.md
person.md
places.md
thoughts.md
media.md
experiences.md
experiences/
life.config.yml
AI_GUIDE.md
```

## 通用原则

1. 保留事实，允许精简，不添油加醋。
2. 用户明确陈述的事实可以直接记录；不明确的身份、到访和坐标必须确认。
3. 所有新日期使用 `YYYY-MM-DD`。
4. 同一天只允许一个日记标题，再次记录时合并到已有条目。
5. 日记保持简洁，人物、地点和经验负责反向链接日记。
6. 外部能力不可用时保留待补充状态，不伪造结果。
7. 修改或删除日记事实后，必须检查相关反向索引。

## 日记

格式：

```markdown
## YYYY-MM-DD
**事件标签·多个标签** · 周X · 农历X

每行一件事，不使用 bullet
```

- 最新日期在最上方。
- 正文保持自然、简洁和事实化。
- 再次记录同一天时去重合并，并更新事件标签。

## 人物

格式：

```markdown
## 人物称呼

**描述：** 用户确认的关系或身份

- [YYYY-MM-DD](diary.md#YYYY-MM-DD) 极简共同经历
```

- 只收录真正共同做过事的人。
- 仅被提及的公众人物、作者或新闻人物不收录。
- 不根据日记自行推断关系。
- 同名或同称呼存在歧义时先确认。
- 每个人内部严格按日期倒序。

## 地点

格式：

```markdown
## 地点名称

- 类型：景区
- 行政区：省市区
- 别名：别名一、别名二
- 坐标：待确认
- [YYYY-MM-DD](diary.md#YYYY-MM-DD) 到访摘要
```

- 只记录确认本人真实到达的地点。
- 计划、愿望、否定、他人到访和普通提及不记录。
- 坐标必须保存坐标系、来源和确认时间。
- 未确认坐标不绘制地图。
- 第一版所有地点统一存放在 `places.md`。

## 感悟

格式：

```markdown
## YYYY-MM-DD 标题

感悟正文
```

感悟记录主观思考，不替代当日日记事实。

## 媒体

媒体按书、电影、游戏和音乐分组，并使用 Markdown 表格。空白占位行不视为真实数据。新记录日期统一使用 `YYYY-MM-DD`。

## 生活经验

- `experiences.md` 保存索引。
- `experiences/` 中一条经验一个文件。
- 新建前先搜索同义主题，优先更新已有经验。
- 区分客观事实、主观感受和仍待验证的信息。
- 健康、法律、投资等高风险内容必须说明边界，个人记录不能替代专业意见。
- 新旧结论冲突时在修订记录中说明，不静默覆盖。

支持状态：`草稿`、`持续更新`、`相对稳定`、`已废弃`。

## 反向索引

```text
人物 / 地点 / 经验 → diary.md#YYYY-MM-DD
```

反向链接目标必须存在；日记本身不添加人物、地点或经验关联行。

## 外部能力

- 农历和地点查询由 `life.config.yml` 中的 capability 决定。
- 密钥只能通过环境变量提供。
- Provider 失败时保存已经明确的事实，并将外部信息标记为待补充。

## 示例请求

- “帮我记一下今天下午去图书馆借了两本书。”
- “补昨天的日记，并同步真正一起去的人。”
- “我只是计划去海边，这个地点先不要加入足迹。”
- “把这次整理书桌的过程沉淀成一条生活经验。”
