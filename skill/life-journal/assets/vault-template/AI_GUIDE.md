# Life Journal 使用规则

本目录以 Markdown 为唯一数据源。执行写入前完整读取本文件和 `life.config.yml`。

## 通用原则

1. 保留事实，允许精简，不文学化改写。
2. 所有新日期使用 `YYYY-MM-DD`。
3. 同一天只允许一个日记标题，再次记录时合并去重。
4. 人物、地点和经验反向链接日记，日记不增加关联行。
5. 身份、真实到访和坐标存在歧义时必须确认。
6. 外部能力失败时保留待补充状态，不伪造结果。

## 日记

```markdown
## YYYY-MM-DD
**事件标签** · 周X · 农历X

每行一件事
```

最新日期在最上方。再次记录同一天时合并到已有条目。

## 人物

```markdown
## 人物称呼

**描述：** 用户确认的身份

- [YYYY-MM-DD](diary.md#YYYY-MM-DD) 共同经历
```

只记录真正共同做过事的人，不根据日记猜测关系。

## 地点

```markdown
## 地点名称

- 类型：类型
- 行政区：行政区
- 坐标：待确认
- [YYYY-MM-DD](diary.md#YYYY-MM-DD) 到访摘要
```

只记录确认本人真实到访的地点。计划、愿望、否定、他人到访和普通提及不记录。

## 感悟

```markdown
## YYYY-MM-DD 标题

感悟正文
```

## 媒体

使用 `media.md` 中已有的 Markdown 表格。空行不视为记录，新日期统一使用 ISO 格式。

## 生活经验

`experiences.md` 保存索引，`experiences/` 中一条经验一个文件。区分事实、主观感受和待验证信息；高风险内容不能替代专业意见。

## 修改与删除

纠正日记事实后同步检查人物、地点和经验索引。删除内容时不得留下失效链接。

## 外部能力

通过 `life.config.yml` 选择 Provider，密钥只从环境变量读取。服务不可用时仍保存已经明确的事实。
